ID Generator

Generate UUID v4, UUID v7, ULID and Nano ID values in bulk, for seeding a database, writing tests or filling in a fixture.

UUID v4 is 122 random bits and nothing else: it is unique, and it sorts arbitrarily. That last part is why inserting v4 keys into a database index scatters writes across the whole B-tree and slows down as the table grows. UUID v7 fixes it by putting a millisecond timestamp in the leading bits, so new identifiers sort at the end and stay index-friendly while remaining unguessable.

ULID solves the same problem in a 26-character Crockford base32 form that is shorter and case-insensitive, and NanoID trades the UUID format for a compact URL-safe string. Everything is generated from the browser’s cryptographic random source, so the values are safe to use as identifiers that must not be guessable.

list_alt How to use ID Generator

  1. Choose the identifier format.
  2. Set how many you need.
  3. Generate, then copy the list.

lightbulb Tips & gotchas

  • UUID v4 is random and unordered. UUID v7 and ULID embed a timestamp, so they sort chronologically — which keeps a database index from fragmenting.
  • Nano ID is shorter than a UUID at comparable collision resistance, which makes it a good fit for URLs.
  • If ids will appear in a URL or be read aloud, prefer ULID or Nano ID over a hyphenated UUID.

help_outline Frequently asked questions

Are these safe to use as primary keys?

Yes. For a large table prefer UUID v7 or ULID over v4, because their time-ordered prefix gives much better index locality on insert.

Can two generated ids collide?

The probability is negligible at any realistic volume. All formats here draw from a cryptographic random source.

Should I use these as security tokens?

A UUID is fine as an unguessable identifier but says nothing about authorisation. For secrets and API keys use a dedicated generator with a stated entropy figure.
