비밀번호 & 시크릿 생성기

강력한 비밀번호, 외우기 쉬운 패스프레이즈, API 키, PIN을 만듭니다. 강도는 모호한 색상 막대가 아니라 실제 엔트로피 비트 수로 보여줍니다. 모든 값은 브라우저의 암호학적 난수 생성기에서 나옵니다.

비밀번호의 강도는 엔트로피 — 공격자가 훑어야 하는 경우의 수 — 로 재고, 엔트로피는 특수문자보다 길이에서 훨씬 많이 나옵니다. 소문자만 쓴 16자 무작위 문자열이 모든 문자 종류를 억지로 넣은 8자보다 엔트로피가 높고, 입력하기도 편합니다.

여기서 쓰는 난수는 Math.random()이 아니라 브라우저의 암호학적 난수원인 crypto.getRandomValues()입니다. Math.random()의 출력은 앞선 값으로부터 예측할 수 있어 비밀에 써서는 안 됩니다. 패스프레이즈 모드는 단어를 조합하는데, 사람이 직접 다시 입력해야 하는 상황이라면 이쪽이 낫습니다. 추정 엔트로피는 비트 단위 숫자로 표시하므로 색깔이 아니라 값으로 판단할 수 있습니다.

list_alt 비밀번호 & 시크릿 생성기 사용법

  1. 모드를 고릅니다. 일반 비밀번호는 랜덤, 외울 것은 패스프레이즈, 서비스 시크릿은 API 키, 숫자만 필요하면 PIN입니다.
  2. 길이나 단어 수를 정하고 어떤 문자 종류를 넣을지 선택합니다.
  3. 여러 개가 필요하면 생성 개수를 지정한 뒤 생성을 누릅니다.
  4. 행의 아이콘으로 하나만 복사하거나 전체 복사를 씁니다.

lightbulb 알아두면 좋은 점

  • 복잡도보다 길이가 중요합니다. 소문자만 쓴 20자가 특수문자를 섞은 10자보다 강하고 입력하기도 훨씬 쉽습니다.
  • 비밀번호를 소리 내어 읽거나 종이·스크린샷에서 옮겨 적어야 한다면 헷갈리는 문자 제외를 켜세요. 0/O와 1/l/I를 빼 줍니다.
  • 패스프레이즈는 엔트로피를 조금 내주고 기억하기 쉬움을 크게 얻는 방식입니다. 이 단어 목록에서 다섯 단어면 약 60비트로, 아무 도움 없이 외워야 하는 용도에는 충분합니다.
  • 해독 시간 추정은 빠른 해시를 대상으로 초당 100억 회 시도하는 오프라인 공격을 가정합니다. bcrypt나 Argon2처럼 느린 해시라면 실제 수치는 훨씬 큽니다.

help_outline 자주 묻는 질문

비밀번호가 서버에서 만들어지나요?

아니요. 브라우저의 crypto.getRandomValues에서 나오며 전송되지 않고 저장되지도 않습니다. 새로고침하면 사라집니다.

엔트로피가 몇 비트면 충분한가요?

대략 이렇습니다. 속도 제한과 2단계 인증이 있는 계정이면 60비트로 충분하고, 중요한 것이라면 80비트 이상, 128비트면 무차별 대입을 논할 필요가 없어집니다. 설정에 따른 정확한 값은 강도 표시에 나옵니다.

문자 중복 없음을 켜면 왜 엔트로피가 떨어지나요?

중복을 금지하면 가능한 조합이 줄어들어 엔트로피가 조금 낮아지고, 길이도 문자 집합 크기를 넘을 수 없게 됩니다. 보안 옵션이 아니라 가독성 옵션입니다.
